# ClipDock 사용 안내

[문서 목록](README.md) · [프로젝트 README](../README.md)

## 지원 기능

- 디스플레이 또는 창 선택, 미리보기, 녹화 시작/중지
- macOS/Windows에서 `창 → 클릭으로 선택`으로 화면에 보이는 창을 직접 지정
- `영역 → 영역 지정`에서 원하는 모니터에 사각형을 드래그하여 해당 부분만 미리보기·녹화합니다. 확장 모니터도 바로 선택할 수 있으며, 드래그한 모니터가 녹화 대상으로 자동 반영됩니다. 하나의 영역은 한 모니터 안에서 선택합니다.
- 일시정지·재개, 경과 시간 표시
- 원본 비율을 유지하는 최대 출력 크기, FPS, 비트레이트 설정
- H.264 또는 MPEG-4 비디오 / MP4 컨테이너
- 선택한 오디오 입력 장치 녹음, AAC 오디오
- 기존 파일 덮어쓰기 방지, 임시 파일에서 녹화 완료 후 최종 이름으로 이동
- 창을 닫을 때 녹화 파일 마무리를 기다린 후 종료
- 단축키: Ctrl/⌘+Shift+R 시작, +P 일시정지/재개, +S 중지. 전역 등록된 키는 다른 앱 사용 중에도 동작합니다.

화면·창·영역의 저장 프레임은 설정한 FPS 간격을 사용합니다. 화면이 정지했거나 캡처 입력이
출력 FPS보다 느리면 마지막 이미지를 반복해 영상 시간을 유지합니다. 새로운 움직임을
보간해 만드는 기능은 아니며, 일시정지한 시간은 저장 영상에서 제외합니다.
단, X11에서 자체 창 제외를 켠 화면·영역 녹화는 아래 보호 경로를 사용하므로 실제 FPS가
설정값보다 낮을 수 있습니다.

## 화면 녹화에서 ClipDock 창 제외

녹화 설정 아래에 두 옵션이 있으며, 재실행 후에도 선택을 기억합니다.

- **ClipDock 창을 녹화에서 제외**: 기본 켜기. Windows 10 버전 2004 이상에서 미리보기·녹화 중
  메인 창과 앱 소유 Qt 대화상자를 캡처에서 제외해 그 뒤의 화면을 담습니다. 중지 후에는 제외를 해제합니다.
  앱 자체 사용법을 녹화하려면 시작 전에 끄세요. 별도 OS 권한 창이나 네이티브 시스템 대화상자까지 제외하는 기능은 아닙니다.
- **녹화 시작 시 최소화**: 기본 끄기. 켜면 권한 준비 후 녹화를 시작할 때 최소화합니다.
  미리보기만 할 때와 저장 대화상자를 취소할 때는 최소화하지 않습니다.
  앱이 최소화한 창은 녹화 종료·시작 실패 후 원래 일반/최대화 상태로 돌아옵니다.

macOS/Linux, 오래된 Windows 또는 제외 설정에 실패한 환경에서는 창 제외가 켜져 있고
ClipDock가 녹화 영역과 겹칠 때 자동 최소화로 대신합니다. 창을 다시 열거나 이동·크기 변경으로 영역과 겹치면
일시정지하고, 재개하면 다시 최소화합니다. 다른 모니터나 녹화 영역 밖에 둔 창은 유지합니다.
Wayland 포털에서 선택한 실제 대상을 앱이 알 수 없으므로 겹치는 것으로 간주합니다.
전역 단축키를 사용할 수 없어도 작업 표시줄/Dock에서 창을 다시 열어 중지할 수 있습니다.
X11의 화면·영역 녹화에서는 별도의 보호 경로를 사용합니다. 창의 실제 표시 상태와 겹침을
화면 취득과 함께 검사하고, 시작·재개 시 Qt의 배경 다시 그리기를 처리한 후 새 프레임만 저장합니다.
표시된 ClipDock 창이나 앱 소유 창이 영역과 겹치는 동안에는 해당 프레임을 저장하지 않습니다.
이때 새 영상 프레임이 없으면 마지막 화면이 유지될 수 있습니다. 창 제외를 끄면 기존 캡처 경로를 사용합니다.

이 대체 동작은 창을 OS 캡처에서 제외하는 기능과 다릅니다. X11에서도 다른 앱의 배경 다시 그리기나
합성 창 관리자의 최소화 애니메이션·잔상까지 완료됐는지는 확인할 수 없습니다.
macOS/Wayland의 시작·재개 및 창 이동·복원 순간도 프레임 제외를 보장하지 않습니다.

캡처에서 제외되지 않은 창이 대상 화면·영역과 겹치면 미리보기 대신 중첩 방지 안내를 표시합니다.
영역 밖으로 옮기면 미리보기가 돌아옵니다. **미리보기를 숨기는 것만으로 창 자체가 녹화에서 제외되지는 않습니다.**
Windows의 제외 기능은 적용 중 다른 캡처 프로그램에서도 ClipDock 창을 숨길 수 있습니다.

## 전역 단축키

Windows는 Ctrl+Shift, macOS는 ⌘+Shift와 R/P/S 조합을 사용합니다. X11도 Ctrl+Shift 조합을 사용합니다.
macOS는 현재 영문 입력 배열의 문자 위치를 사용하며 배열이 바뀌면 다시 등록합니다.
전역 시작은 기존 저장 파일 선택 창을 엽니다. 일시정지·재개와 중지는 ClipDock로 포커스를 옮기지 않고 사용할 수 있습니다.

- 화면 아래의 `전역 단축키 N/3`에 마우스를 올리거나 **도움말 → 단축키 상태**에서 키별 등록 결과를 확인합니다.
- 다른 앱과 충돌해 등록하지 못한 키만 앱 내부 단축키로 남습니다. 해당 앱의 단축키 설정을 바꾼 뒤 **도움말 → 전역 단축키 다시 등록**을 실행할 수 있습니다.
- 키를 계속 누르고 있어도 명령을 반복 실행하지 않습니다. 저장 대화상자·영역/창 선택 중에는 녹화 단축키를 실행하지 않으며, 파일 마무리 중에는 중복 명령을 차단합니다.
- X11에서는 먼저 누른 R/P/S 키를 놓은 뒤 다음 단축키를 누르세요. 한 키를 누른 채 다른 명령을 겹쳐 누르면 두 번째 명령은 무시합니다.
- 앱이 종료되면 전역 등록도 해제됩니다. 키 조합을 직접 바꾸는 앱 설정 화면은 아직 제공하지 않습니다.

Wayland 및 Wayland에서 실행한 XWayland 앱은 데스크톱의 **GlobalShortcuts 포털**을 사용합니다.
지원되는 환경에서는 시스템 승인 창에서 키를 지정하며, 시스템에서 배정한 실제 키는 단축키 상태에 표시됩니다.
포털 미지원, 등록 취소·거부, 서비스 종료 시 앱 내부 단축키로 돌아갑니다. 데스크톱 환경에 따라 지원 여부와 승인 UI가 다릅니다.

샌드박스 밖의 Linux 앱을 식별하려면 `io.github.pryaoh.ClipDock.desktop`이 데스크톱의 애플리케이션 검색 경로에 있어야 할 수 있습니다.
패키지의 `share/applications/`에 이 파일을 포함하며, 일반적인 시스템 설치에서는 자동으로 설치됩니다.
압축 배포본을 직접 실행하는 경우 이 파일을 `~/.local/share/applications/`에 복사하고 `Exec`를 실제 실행 파일 경로로 지정한 뒤 메뉴에서 실행할 수 있습니다.
이는 설치파일 생성과 별개의 데스크톱 등록입니다.

## macOS 권한

최초 캡처 시 시스템 설정 → 개인정보 보호 및 보안 → 화면 및 시스템 오디오 기록에서
ClipDock를 허용합니다. 필요하면 앱을 완전히 종료하고 다시 실행합니다.
Swift 초안과 Qt 앱의 권한 항목은 서로 다릅니다.

권한 스위치가 켜져 있는데 미리보기가 거부되면
[macOS 권한 문제 해결](TroubleShooting.md)을 참고하세요.

## Windows 권한과 실행 환경

마이크가 동작하지 않으면 Windows 설정 → 개인정보 및 보안 → 마이크에서
데스크톱 앱의 마이크 접근을 허용합니다. 실제 화면·창 캡처에는 로컬 대화형 데스크톱이 필요합니다.

## Linux 캡처 환경

- **X11:** 화면·창 목록 선택, 영역 드래그 녹화를 사용합니다. 창을 직접 클릭하는 선택기는 macOS/Windows용입니다.
- **Wayland:** 미리보기 또는 녹화 시작 후 시스템 공유 창에서 대상을 선택합니다.
  앱의 모니터 목록과 영역 지정은 사용하지 않습니다. 공유 선택 창을 기다리는 동안 자동으로 시간 초과하지 않으며
  앱의 중지 버튼으로 취소할 수 있습니다. Qt 6.8의 Wayland 화면 캡처는 실험적 기능입니다.
- Wayland에는 실행 중인 PipeWire와 데스크톱에 맞는 ScreenCast 포털 백엔드가 필요합니다.
  Ubuntu GNOME은 `pipewire`, `xdg-desktop-portal`, `xdg-desktop-portal-gnome` 패키지를 사용합니다.
  KDE는 KDE 포털 백엔드를 사용하세요. 설치 후 로그아웃·로그인하여 사용자 서비스를 시작합니다.
- 마이크는 PulseAudio 또는 PipeWire의 PulseAudio 호환 서비스(`pipewire-pulse`)를 사용합니다.
  실제 화면 공유는 그래픽 데스크톱 세션에서 실행해야 합니다.
